Recognising Daily Activities from Smartphone Sensors

Author

STAT5003

Published

September 3, 2026

1. Framing and dataset selection

1.1 Real-world classification task

This project investigates whether a person’s activity can be classified from measurements derived from a waist-mounted smartphone’s accelerometer and gyroscope. The response has six categories: Walking, Walking upstairs, Walking downstairs, Sitting, Standing, and Laying. The categories have no complete natural order, so this is a nominal multi-class classification problem.

1.2 Research question

How accurately can six common daily activities be classified from time- and frequency-domain smartphone sensor features for people who were not used to train the model?

The final phrase is important. Multiple windows come from each participant, so a random row split could put the same person’s movement patterns in both training and test data. The supplied participant-level split provides a more realistic assessment of generalisation to unseen people.

1.3 Motivation and stakeholders

Human activity recognition can support fitness tracking, context-aware mobile applications, workplace-safety systems, and—after suitable clinical validation—monitoring of mobility or rehabilitation. Stakeholders include device developers, researchers, clinicians, service providers, and people whose movements are measured.

The analysis is a controlled-laboratory benchmark, not a clinical diagnostic system. Errors could lead to misleading health or safety inferences, while continuous motion sensing creates privacy and surveillance risks. Deployment would require consent, data minimisation, secure storage, testing on the intended population, and a clear way for users to opt out.

2. Data source and provenance

The Human Activity Recognition Using Smartphones dataset is published by the UCI Machine Learning Repository. It was created from 30 volunteers aged 19–48 who performed six activities while wearing a Samsung Galaxy S II on the waist. Accelerometer and gyroscope signals were recorded at 50 Hz. Fixed-width windows of 2.56 seconds with 50% overlap were transformed into 561 time- and frequency-domain features.

The local file UCI_HAR_Dataset.zip was downloaded from UCI’s official distribution endpoint. Its SHA-256 checksum is:

C00B803081A5C797CD5E4B83700A9810B38D53D9D84E01917E090E1FDBC81031

The data were originally described by Anguita et al. (2013). UCI distributes an established split containing 70% of the volunteers in training and 30% in testing. The local files contain 7,352 training windows and 2,947 test windows.

This source is not Kaggle, is not a built-in R dataset, and does not concern the prohibited assignment topics.

3. Data import and integrity checks

The UCI download contains a second ZIP archive. The code extracts both layers to the R session’s temporary directory, reads the supplied metadata, and combines the training and test portions while preserving their original roles.

stopifnot(file.exists(data_zip))

extract_root <- file.path(tempdir(), "uci_har_240")

  extract_root,
  pattern = "UCI HAR Dataset[.]zip$",
  full.names = TRUE

unzip(inner_zip, exdir = extract_root, overwrite = TRUE)
data_dir <- file.path(extract_root, "UCI HAR Dataset")

feature_key <- read.table(
  file.path(data_dir, "features.txt"),
  col.names = c("feature_id", "feature_name"),
  stringsAsFactors = FALSE
)
activity_key <- read.table(
  file.path(data_dir, "activity_labels.txt"),
  col.names = c("activity_id", "activity"),
  stringsAsFactors = FALSE
)

# Eighty-four labels are repeated in the supplied feature metadata.
# make.unique() preserves all 561 columns while giving R valid unique names.
feature_names <- make.unique(feature_key$feature_name, sep = "__duplicate_")

read_partition <- function(partition) {
  x <- read.table(file.path(data_dir, partition, paste0("X_", partition, ".txt")))
  names(x) <- feature_names
  y <- scan(file.path(data_dir, partition, paste0("y_", partition, ".txt")),
            quiet = TRUE)
  subject <- scan(
    file.path(data_dir, partition, paste0("subject_", partition, ".txt")),
    quiet = TRUE
  )

  bind_cols(
    tibble(partition = partition, subject = subject, activity_id = y),
    as_tibble(x, .name_repair = "minimal")
  ) |>
    left_join(activity_key, by = "activity_id") |>
    relocate(activity, .after = activity_id)
}

har <- bind_rows(read_partition("train"), read_partition("test")) |>
  mutate(
    partition = factor(partition, levels = c("train", "test")),
    activity = factor(activity, levels = activity_key$activity)
  )

4.2 High dimensionality and redundancy

All 561 predictors are numeric summaries of sensor windows. They include means, standard deviations, signal-magnitude areas, correlations, autoregressive coefficients, frequency components, entropy measures, and angle variables. Having many transformations of related signals creates strong correlation and multicollinearity.

4.3 Low-dimensional view of the activity structure

Principal component analysis (PCA) gives a compact view of the 561-dimensional feature space. The PCA below is fitted only to the training data and then applied unchanged to the held-out participants.

train_index <- har$partition == "train"
pca_fit <- prcomp(
  har[train_index, predictor_names],
  center = TRUE,
  scale. = TRUE
)

pca_scores <- predict(pca_fit, newdata = har[predictor_names])[, 1:2] |>
  as_tibble() |>
  bind_cols(har |> select(activity, partition))

explained <- 100 * pca_fit$sdev^2 / sum(pca_fit$sdev^2)

The plot is descriptive rather than a performance result. Separation in two components does not imply that a two-variable classifier is sufficient, and overlap is expected between the closely related postural classes SITTING and STANDING.

5. Planned data preparation

  1. Retain UCI’s participant-level training and test split; do not randomly repartition individual windows.
  2. Keep the test partition untouched until all model and preprocessing choices are final.
  3. Repair duplicated feature names reproducibly and retain a mapping to the original metadata.
  4. Estimate centring, scaling, PCA, correlation filtering, and any other feature selection using training data only.
  5. Remove zero-variance predictors if present and consider a correlation filter or PCA for linear models.
  6. Use grouped cross-validation by subject inside the training partition so validation participants are unseen during each fold.
  7. Preserve all six response categories and report class-specific errors.

Because overlapping time windows from one participant are dependent, treating all 10,299 rows as independent observations would exaggerate the effective sample size. Statistical inference and uncertainty estimates must respect participant clustering.

6. Modelling decisions informed by EDA

A suitable baseline is multinomial logistic regression after training-only standardisation and dimensionality reduction. A regularised multinomial model provides a stronger linear comparator. A tree-based method such as random forest or gradient boosting can model non-linear relationships and interactions, while support-vector machines are also plausible for this high-dimensional feature space.

Model tuning should use grouped cross-validation by participant. Final evaluation should use the supplied test participants once. Recommended metrics are:

  • overall accuracy and macro F1;
  • balanced accuracy;
  • per-class precision and recall;
  • a six-by-six confusion matrix;
  • accuracy by held-out participant.

The most informative errors are likely to be within the three dynamic activities or between sitting and standing. Confusing a static posture with a dynamic activity is qualitatively different from confusing two similar walking conditions, so the confusion matrix should accompany every aggregate metric.

7. Strengths, limitations, and ethics

Strengths

  • It meets exactly three assignment requirements with objective numerical evidence.
  • At about 59 MB compressed and 10,299 rows, it is practical on an ordinary laptop.
  • The official subject-level split supports a defensible generalisation question.
  • Classes are reasonably balanced and labels were assigned using video recordings.
  • The 561 features provide substantial scope for dimensionality and correlation analysis.

Limitations

  • Only 30 participants aged 19–48 were studied, limiting population diversity.
  • Activities were scripted in controlled conditions, so performance may fall in free-living settings.
  • The phone was fixed at the waist; results may not transfer to a pocket, bag, wrist, or another device.
  • Overlapping windows are correlated and must not be treated as fully independent.
  • Engineered features conceal some raw-signal detail and include highly redundant transformations.
  • The dataset has no missing values, so it offers less opportunity to demonstrate missing-data methods.

Ethical considerations

Motion data may reveal health conditions, routines, location-linked behaviour, or sensitive daily patterns. A deployed system would require informed consent, purpose limitation, secure processing, and explicit restrictions on employer, insurer, or surveillance use. Performance should be validated across ages, body types, mobility levels, devices, and carrying positions before consequential use.

8. Overall recommendation

This dataset is a strong lower-workload alternative to BRFSS. It satisfies the Large, Complex, and Multi-class criteria directly while remaining small enough for rapid iteration. Its clean structure shifts the analytical emphasis from missing-data processing to leakage-aware validation, high-dimensional feature reduction, correlated predictors, and participant-level generalisation. The project is particularly suitable if the group wants a technically rigorous classification problem without the memory and coding burden of the 2024 BRFSS file.

1. Retain UCI's participant-level training and test split; do not randomly repartition individual windows.
2. Keep the test partition untouched until all model and preprocessing choices are final.
3. Repair duplicated feature names reproducibly and retain a mapping to the original metadata.
4. Estimate centring, scaling, PCA, correlation filtering, and any other feature selection using training data only.
5. Remove zero-variance predictors if present and consider a correlation filter or PCA for linear models.
6. Use grouped cross-validation by `subject` inside the training partition so validation participants are unseen during each fold.
7. Preserve all six response categories and report class-specific errors.

Because overlapping time windows from one participant are dependent, treating all 10,299 rows as independent observations would exaggerate the effective sample size. Statistical inference and uncertainty estimates must respect participant clustering.

## 6. Modelling decisions informed by EDA

A suitable baseline is multinomial logistic regression after training-only standardisation and dimensionality reduction. A regularised multinomial model provides a stronger linear comparator. A tree-based method such as random forest or gradient boosting can model non-linear relationships and interactions, while support-vector machines are also plausible for this high-dimensional feature space.

Model tuning should use grouped cross-validation by participant. Final evaluation should use the supplied test participants once. Recommended metrics are:

- overall accuracy and macro F1;
- balanced accuracy;
- per-class precision and recall;
- a six-by-six confusion matrix;
- accuracy by held-out participant.

The most informative errors are likely to be within the three dynamic activities or between sitting and standing. Confusing a static posture with a dynamic activity is qualitatively different from confusing two similar walking conditions, so the confusion matrix should accompany every aggregate metric.

## 7. Strengths, limitations, and ethics

### Strengths

- It meets exactly three assignment requirements with objective numerical evidence.
- At about 59 MB compressed and 10,299 rows, it is practical on an ordinary laptop.
- The official subject-level split supports a defensible generalisation question.
- Classes are reasonably balanced and labels were assigned using video recordings.
- The 561 features provide substantial scope for dimensionality and correlation analysis.

### Limitations

- Only 30 participants aged 19–48 were studied, limiting population diversity.
- Activities were scripted in controlled conditions, so performance may fall in free-living settings.
- The phone was fixed at the waist; results may not transfer to a pocket, bag, wrist, or another device.
- Overlapping windows are correlated and must not be treated as fully independent.
- Engineered features conceal some raw-signal detail and include highly redundant transformations.
- The dataset has no missing values, so it offers less opportunity to demonstrate missing-data methods.

### Ethical considerations

Motion data may reveal health conditions, routines, location-linked behaviour, or sensitive daily patterns. A deployed system would require informed consent, purpose limitation, secure processing, and explicit restrictions on employer, insurer, or surveillance use. Performance should be validated across ages, body types, mobility levels, devices, and carrying positions before consequential use.

## 8. Overall recommendation

This dataset is a strong lower-workload alternative to BRFSS. It satisfies the **Large**, **Complex**, and **Multi-class** criteria directly while remaining small enough for rapid iteration. Its clean structure shifts the analytical emphasis from missing-data processing to leakage-aware validation, high-dimensional feature reduction, correlated predictors, and participant-level generalisation. The project is particularly suitable if the group wants a technically rigorous classification problem without the memory and coding burden of the 2024 BRFSS file.
